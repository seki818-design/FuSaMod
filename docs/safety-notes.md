# 安全規格上の位置づけ・制限事項

## ツールの位置づけ(ISO 26262-8 第 11 章 ソフトウェアツールの信頼性評価)
本ツールは安全分析の**支援ツール**であり、成果物(FMEA・FTA・ASIL 判定)の最終責任は利用者にある。
- 想定利用ケース: 安全分析データの作成・整合性検査・可視化。ツールの出力は設計成果物へ入る(TI は 1 ではない可能性)。
- 誤りの検出手段(TD): 整合性チェック(指摘タブ)、HARA の ASIL 表の自動テスト、利用者によるレビュー。ただし**検出が確実とは主張しない**。
- 暫定の提案: TD2 以上を想定し、**組織の手順で ASIL 判定と FMEA の独立レビュー**を必ず行う。ツール認定(TCL 判定)は組織の安全マネージャーが実施すること。本リポジトリは認定の証拠を提供しない。
- 検証の根拠: ASIL 決定表・デコンポジション表・最小カットセット・AP 表検証のユニットテストと、公式 SysML 実装による結合テスト(`docs/quality/evidence/`)。

## 既知の制限
- AP(Action Priority)表は同梱しない(AIAG-VDA の表は著作物のため)。利用者が用意し、`compileApTable` が網羅性・重複・単調性を検証する。未設定時は RPN のみ表示。
- 確率計算(FTA)は独立事象を仮定する簡易計算。共通原因故障は別途扱う。
- ASIL デコンポジションの独立性は「根拠の記録と有無の検査」までで、独立性の妥当性そのものは判定しない。
- SCDL は v1.6.0 の概念を SysML v2 のステレオタイプで表現した独自写像であり、ASAM の公式ツールとの相互運用は確認していない。
- AI 提案は誤りうる。承認前に必ず人が確認する。
- 実際の利用者による使い勝手の評価、および規格適合の第三者確認は未実施。

## ツールが検出する誤り / 検出しない誤り(2026-10 時点)

**検出する(指摘タブに出る)**

| 分野 | 検出する誤り |
|---|---|
| HARA | S/E/C の範囲外・欠落、ASIL の付いた事象に安全目標が無い、安全目標の ASIL と事象の最大 ASIL の不一致、FTTI・安全状態の未設定 |
| ASIL 継承 | 要求の ASIL が上位・安全目標より低い(分解によらない引き下げ)、元 ASIL の偽装(分解に属さない `A(D)`)、ASIL 付きの安全目標に要求が無い、親子の循環 |
| デコンポジション | 表にない組み合わせ、元 ASIL の不一致、同一要素・祖先/子孫の要素への配置、未配置、独立性の根拠の欠落(エラー)と形だけの根拠(警告)、分解先が分解元の子でない、再利用・二重分解・自己分解・循環 |
| FTA | 循環、未知のノード、入力の無いゲート、件数・時間の打ち切り(いずれも「結果は不完全」。0 件を安全と表示しない) |
| FMEA・ネット | 上下のリンクの範囲外、故障ノードの孤立、機能の分解漏れ、AP 表の網羅性・重複・単調性、AP 表が非公式/出典未確認(画面・CSV・レポートに明記) |
| 参照 | 存在しない要素・故障ノード・要求への参照、ID の重複 |

**検出しない(人が判断する)**

- 独立性の根拠が**内容として妥当か**(文字列の形式のみ検査)。依存故障解析(DFA)・FFI そのものの正しさ。
- 故障モードの網羅性、S/O/D の評価値の妥当性、安全機構が故障を**物理的に**検出・対処できるか(例: 短絡故障をゲート遮断で対処できるか)。`coversFailureIds` は参照の存在のみ検査。`diagnosticCoverage` は記録のみで、集計(SPFM/LFM/PMHF)はしない。
- FMEA で複数の影響を持つ故障の重大度は、最上位の影響から継承した**最大値 1 つ**で扱う(影響ごとの重大度は持たない)。
- パズルビューの「整合」は、**このツールが検査している範囲**で指摘が無いことを示す。検査していない領域(上記)は整合と区別されない。

## AI の扱い

- AI は提案のみ。承認した変更には、**提案者(依頼した人)・承認者・時刻・AI の提供元**が `safety.json` の `aiChanges` と監査ログに残る。`FUSAMOD_AI_SEPARATE_APPROVER=1` で、依頼した本人による承認を禁止できる(認証を設定しているとき)。
- AI の提案を承認しても、**新しいエラーが増える提案は適用されない**。ただし、承認者が内容の妥当性を確認する責任は変わらない。
