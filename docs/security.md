# セキュリティ(脅威モデルと対策)

## 前提
- 想定する使い方: 組織内の少人数が使う Web アプリ。既定はローカル専用(`HOST=127.0.0.1`、認証なし)。ネットワークに公開するときは TLS 終端のリバースプロキシと `FUSAMOD_TOKENS` が必須(docs/operations.md)。
- 守る資産: 安全分析データ(モデル、safety.json)、履歴、監査ログ、(Claude 利用時の)API キーとプロジェクト内容。

## 脅威と対策

| 脅威 | 対策 | 確認 |
|---|---|---|
| 認証の回避(URL の書き換え: `/%61pi`、二重エンコード、`//`、`./`、`;`、`\`、`%00`、絶対 URI、メソッド上書き) | 認証・役割の判定を、**デコードして正規化したパス**と**ルーターが選んだルート**の両方で行う既定拒否。`/api` 配下は health 以外すべて認証 | 全ルート × {匿名, viewer, editor} の厳密な表、書き方 11 通りの表駆動テスト |
| トークンの総当たり | 認証失敗は 1 分に 10 回まで(超えると 429)。トークンは 16 文字以上、定数時間で比較。失敗は監査ログ(`_server-audit.jsonl`)に記録 | テスト |
| 役割の逸脱(viewer による書き込み) | viewer は GET と解析(`/analyze`)のみ。書き込み系は 403。UI も無効化 | テスト |
| 秘密情報の漏えい | ログの `authorization` を伏せる。トークンを利用者名として記録しない(書式の検証)。`/api` の応答は `Cache-Control: no-store` | テスト |
| パストラバーサル | プロジェクト ID は `^[a-z0-9][a-z0-9-]{0,63}$`。参照資料は実パスがルート配下であることを確認。出力名は許可リスト | テスト |
| 過大な入力 | 本文 5MB、モデル 2MB(解析前に検査)、zod の strict な検証、プロトタイプ汚染の拒否 | テスト |
| XSS・インジェクション | `innerHTML` を使わない(React のエスケープ)。CSP(`default-src 'self'`)。CSV は数式として解釈されないよう無害化 | E2E、テスト |
| 監査ログの改ざん | 各行に直前の行のハッシュ(連鎖)。`chain` で検証。**末尾の削除・全面的な作り直しは検出できない**(外部への転送で補う) | テスト |
| 保存の途中での障害 | 履歴を先に確定してから現在のファイルを更新。壊れた履歴は隔離し通知 | テスト |
| 依存の脆弱性 | `pnpm audit --prod`(CI) | CI |
| AI | 提案のみ。承認が必要。承認時に新しいエラーが増えれば拒否。リスクを下げる変更(評価値の低下・分解の追加・削除など)は確認が必要。`FUSAMOD_AI_SEPARATE_APPROVER` で依頼者本人の承認を禁止。来歴(`aiChanges`)は**サーバーだけが書き**、保存・復元で追加・削除・書き換えできない。Claude 利用時は内容が外部 API に送られる | テスト |

## 監査の対象
記録する: 作成・保存(**人の保存も、評価値・HARA・ASIL・確率・管理策・削除などの差分とリスク低下の件数つき**)・復元・エクスポート(同じ人の同じ書き出しは 1 分に 1 回)・AI の提案/承認/却下・履歴の自動削除/隔離・認証失敗(サーバー全体のログ、最初の 20 件以降は間引き)。
**記録しない**: GET による閲覧(量が多いため)。必要なら、リバースプロキシのアクセスログで補う。

## プロキシの背後
`FUSAMOD_TRUST_PROXY`(`true` か `1` = 直前のプロキシ 1 段、2〜10 = その段数まで)を設定すると、接続元 IP(レート制限・監査)を `X-Forwarded-For` から取る。**設定しないときは `X-Forwarded-For` を信用しない**(偽装による制限の回避を防ぐ)。**直接インターネットに公開するサーバーで `true` を設定してはいけない**（X-Forwarded-For を偽装され、認証失敗の制限（10 回/分）を回避される。実測）。信頼できるプロキシが X-Forwarded-For を上書き/付加する構成でのみ使うこと。ホップ数は関数で Fastify に渡している(数値のままだと無視されるため)。`apps/server/test/api.test.ts` で、未設定・`true`・`1` の挙動を確認している。

## 既知の限界
- 利用者の認証はベアラートークンのみ(SSO・パスワード・トークンの失効の仕組みなし。変更はサーバーの再起動)。
- レート制限はプロセス内(複数プロセスで共有しない)。
- 圧縮配信なし(プロキシで行う)。
- 第三者による脆弱性診断は未実施。

## 標準形式への変換のリソース制御
`model.json` / `model.xmi` は Java の子プロセスを起動するため、**同時に 2 件まで、待ちは 4 件まで**(超えると 429)。タイムアウト(180 秒)ではプロセスグループごと停止する。起動時に前回の異常終了で残った一時ディレクトリを掃除する。viewer も実行できる(読み取り操作のため)ので、レート制限(1 分に 600 回)と上の同時実行の上限で守る。
