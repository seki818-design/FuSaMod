# 利用ガイド

## 起動

```sh
pnpm install
pnpm build            # Web UI をビルド
pnpm start            # http://127.0.0.1:8787(.env.example の環境変数で設定)
```

Java 21 が無くても動きます(同梱のスナップショット解析に縮退。モデルの編集・再解析は公式 SysML 実装が必要です。画面上部に現在のモードが表示されます)。

## 画面

| 領域 | 内容 |
|---|---|
| エクスプローラ | プロジェクト・構造要素の木。選択した要素が分析対象になる |
| ビューペース | 構造図(入れ子)/ SysML テキスト。テキストは 0.7 秒後に自動で解析される |
| 分析タブ | FMEA / ネット / FTA / HARA / コンセプト(意図機能と安全機構のペア、ASIL デコンポジション)/ SCDL / トレース / 指摘 / 履歴 / データ |
| パズルビュー | 4 視点(要求・構造・振る舞い・安全)× 4 階層の整合状態。セルをクリックすると該当の指摘に移動。「階層間の整合性」のオン/オフが可能 |
| AI | 質問や提案依頼を送る。AI は**提案するだけ**で、承認するまでデータは変わらない |

## 基本の流れ

1. SysML でシステムの入れ子(`part`)、機能(`action` と `perform`)、要求(`satisfy`)を記述して保存。
2. 構造ネット・機能ネットが自動導出される(規約は ADR-0008)。
3. 「データ」タブまたは AI の提案で、故障モード・原因/影響リンク(エラーネット)を入れる。FMEA は選択要素ごとに**ネットの射影**として表示され、上位の影響・下位の原因が自動でつながる。
4. 重大度は最上位の影響から継承される。発生度・検出度はリンクごとに入れる。AP は利用者が用意した AP 表(`apTable`)で評価する(**正式な表は同梱していません**。サンプルの表は動作確認用の非公式の玩具で、画面に「非公式」と表示されます。ADR-0004)。
5. HARA で ASIL を決定し、安全目標・安全要求・デコンポジション・ペアリングを「コンセプト」で管理。独立性の根拠も記録できる。
6. 「指摘」タブの警告・エラーを解消する。保存は「保存」ボタン(他の人が先に更新した場合は競合として通知され、編集内容は残る)。

## AI の使い方と注意

- 既定は外部通信の無いルールベース。`FUSAMOD_AI_PROVIDER=claude` で Claude を使用(API キーが必要)。この場合、**モデルと参照資料の抜粋が外部 API に送信されます**。機密の扱いは組織のルールに従ってください。
- 提案には根拠(参照資料の引用)が付く。承認すると、新たなエラーが増える提案は拒否される。すべての操作は監査ログ(`audit.jsonl`)に残る。

## エクスポート

「データ」タブから FMEA / トレース / 指摘の CSV、Markdown レポート、SCDL の SysML テキストを取得できる。CSV はスプレッドシートの数式として解釈されないよう無害化している。
